## 一、项目背景

### 1.1 问题陈述

在全球范围内，AI 教育资源的分布极不均衡：
- 发达地区学校配备高端 GPU 集群，学生可接触 ChatGPT、Gemini 等先进 AI 工具
- 欠发达地区学校缺乏基本 IT 设施，普通 CPU 电脑（4GB 内存）无法运行任何 AI 教学应用
- 数字鸿沟正在加剧教育不平等——AI 教育成了"奢侈品"

中国西部山区、农村地区学校同样面临这一困境：老旧电脑、网络不稳定、经费不足，使 AI 教育难以落地。

### 1.2 核心理念

**LumiLearn 提出"算力平权"（Computing Power Equity）理念**：
> 让每一台老旧电脑都能成为 AI 教学终端，让每一个学生都能平等地获得 AI 辅助教育。

### 1.3 项目定位

LumiLearn 是一款面向 AI+教育场景的开源多 Agent 学习平台，由一名高中生独立完成开发。项目聚焦于：
- **低硬件门槛**：4GB 内存、无独显即可运行
- **全栈自主**：从零训练自研 Transformer 模型
- **零外部依赖**：纯 Python RAG 检索，不依赖向量数据库
- **完整教学闭环**：讲解 → 练习 → 评分 → 反馈 → 个性化推荐

## 二、需求分析

### 2.1 目标用户

| 用户群体 | 核心需求 |
|---------|---------|
| 欠发达地区学校 | 低成本 AI 教学工具，无需高端硬件 |
| 家庭自学者 | 个性化学习路径，自适应难度调整 |
| 教师 | 教学辅助工具，自动生成练习题和解析 |
| 学生 | 交互式学习体验，费曼五步引导法 |

### 2.2 功能需求

1. **智能讲解**：输入学科和章节，自动生成知识点讲解
2. **费曼五步法**：现象引入 → 认知冲突 → 思维模型 → 自主推导 → 费曼测试
3. **RAG 知识库**：有据可查的教学内容，避免幻觉
4. **多 Agent 协作**：教学 Agent + 评分 Agent + 建议 Agent
5. **学习分析**：掌握度可视化、薄弱点追踪
6. **自适应难度**：根据学生水平动态调整
7. **错题回流**：错题入库，形成个性化学习路径

### 2.3 非功能需求

| 需求类型 | 要求 |
|---------|------|
| 硬件兼容 | 4GB RAM + 4 核 CPU 即可运行 |
| 部署便捷 | 一键脚本，无需 Docker（可选） |
| 数据隐私 | SQLite 本地存储，不上传云端 |
| 安全性 | 生产环境 SECRET_KEY 强制环境变量 |
| 可观测性 | Agent Trace 可视化、自动化评测 |

## 三、技术方案

### 3.1 整体架构

```
┌─────────────────────────────────────────────────────────────┐
│                         前端展示层                            │
│  classroom.html  │  lumiterm.html  │  admin.html             │
├─────────────────────────────────────────────────────────────┤
│                        API 网关层                            │
│  Flask Blueprints: /api/learn │ /api/analytics │ /api/admin │
├─────────────────────────────────────────────────────────────┤
│                        业务逻辑层                            │
│  FeynmanEngine │ RAG检索(BM25) │ SecurityGW                  │
├─────────────────────────────────────────────────────────────┤
│                        Agent 协作层                          │
│  FeynmanAgent → SelfCritique → CoachAgent                    │
├─────────────────────────────────────────────────────────────┤
│                        模型推理层                            │
│  Ollama(本地) │ 云端API │ 自研8M Transformer                  │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 核心技术栈

| 层级 | 技术选型 | 说明 |
|------|---------|------|
| 前端 | 原生 HTML/CSS/JS + Reveal.js + KaTeX + ECharts | 零外部 CDN，全部本地化 |
| 后端 | Python 3.10+ / Flask / SQLite | 轻量级，零外部依赖 |
| 模型推理 | Ollama + Qwen2.5-1.5B (Q8_0) | 本地 CPU 推理 |
| 自研模型 | PyTorch GPT-2 风格 Transformer | 8 层 8 头，8M 参数 |
| 检索引擎 | 纯 Python BM25 + 同义词扩展 | 零向量数据库依赖 |
| 工作流编排 | LangGraph | Agent 协作 + 降级策略 |

### 3.3 关键算法

#### 3.3.1 费曼五步教学法

```python
# 每步教学策略
STEPS = {
    "phenomenon": "从生活场景引入知识点",
    "conflict": "制造认知冲突，激发思考",
    "model": "构建思维模型/公式",
    "derive": "引导学生自主推导",
    "test": "费曼测试，检验理解"
}
```

#### 3.3.2 RAG 知识检索

```
用户问题 → 同义词扩展（OR语义） → BM25 倒排索引 → 召回 Top-K → 注入 Prompt
```

- 覆盖数学/物理/化学 3 个学科
- 96 组核心术语同义词库
- 1,166 条已发布知识条目
- 真实环境 5/5 检索命中率

#### 3.3.3 Self-Critique 质量评分

```
启发式评分（无模型时）:
  基础分 50  +  长度评估(±30)  +  空泛词检测(−30)  +  知识点命中(+20)  +  主题词(+10)
```

评分 < 70 分时自动重试（最多 2 次），最终结果记录至 trace。

#### 3.3.4 多 Agent 协作编排

```
学生输入 ─→ FeynmanTeacher（教学）─→ SelfCritique（评分）─→ CoachAgent（建议）─→ 聚合报告
    │ RAG 注入      │  五维评估          │  掌握度推荐
```

- 每个 Agent 可配置不同模型
- 单 Agent 异常不阻塞后续（agent_trace 记录 ok/skipped/failed）
- 超时 60s/Agent、8000 token 预算

### 3.4 低配硬件适配

| 优化手段 | 效果 |
|---------|------|
| 1.5B 参数模型 Q8_0 量化 | 模型体积 1.6GB（vs 4.7GB），内存占用 1.77GB |
| num_predict 上限控制 | 单次输出 120 tokens，推理速度 34 tok/s |
| 分层记忆系统 | 短期会话（24h）/ 中期单元 / 长期错题 |
| Lite 模式 | 按需加载，降低常驻内存 |
| SQLite 单文件数据库 | 无需额外数据库服务 |

**实测结果**（AMD Ryzen 7 7840HS，无独显）：
- 推理速度：34.3 tok/s
- 内存峰值：1.77 GB
- 多端口并发：7 个服务同时运行（18080/18081/18082/5000/5001/5010/18090）

## 五、创新点

### 5.1 技术层面

| 创新点 | 说明 |
|--------|------|
| **知识分层拆解流水线** | 章节粗切 → 知识点细切 → 格式校验 → 去重/冲突检测 |
| **双路校验机制** | 主模型生成 + 校验子模型独立复核，双重把关输出质量 |
| **Trace + 自动评测闭环** | 知识点召回率、出题合格率、错题识别准确率量化评估 |
| **多基座自适应调度** | 按任务类型路由到合适的模型基座，失败时自动降级 |
| **纯 Python RAG** | 零外部依赖，不引入向量数据库，BM25 + 同义词扩展 |

### 5.2 教育层面

| 创新点 | 说明 |
|--------|------|
| **费曼五步教学法** | 将认知科学理论转化为可执行的多 Agent 工作流 |
| **Self-Critique 闭环** | 输出质量自动评分，低于阈值触发重试，形成质量保障闭环 |
| **自适应难度** | 根据学生掌握度动态调整题目难度和学习路径 |
| **错题回流** | 错题入库，形成个性化学习路径，避免重复错误 |

### 5.3 工程层面

| 创新点 | 说明 |
|--------|------|
| **一键部署** | `curl ... | bash` 或 `irm ... | iex`，无需手动下载任何文件 |
| **零文件部署** | 管道模式自动克隆/更新仓库，配置走环境变量 |
| **安全合规** | 密钥走环境变量、生产环境 SECRET_KEY 强制注入、统一活动日志 |
| **可观测性** | Agent Trace 可视化面板、自动化评测报表（ECharts） |
