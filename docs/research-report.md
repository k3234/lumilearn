# LumiLearn 科创研究报告（research-report.md）

> 面向国内高中数理化学科自学场景的本地优先 AI 教育系统
> 基于 OpenMAIC 的 MAIC 多智能体课堂范式完成应用层工程改良
> 开发者：一名高一学生（选科物化生）
> 日期：2026-08-23

---

## 摘要

本项目 LumiLearn 是一套可在普通 CPU 上运行的 AI 教育系统，聚焦国内高中数理化学科的自学场景。系统借鉴 OpenMAIC 所提出的 MAIC（Multi-Agent Interactive Classroom）多智能体交互式课堂范式，并未提出全新范式，而是在应用层完成三项工程改良：①Ollama 本地 / 云端 API 双模式适配；②面向国内高中数理化学科的自学业务流程适配；③学情数据回流，自进化知识库闭环，动态调整授课难度。系统实现了"教—学—评—导"完整闭环：费曼五步教学 → 学生主动作答 → 五维评分 → 学习报告，并内置幻觉风险提示与数据本地存储。

**关键词**：多智能体课堂；费曼学习法；CPU 推理；教育智能体；学情闭环

## 一、研究背景与问题

AI 教育目前普遍依赖 GPU 与云端大模型 API，存在三重落地障碍：

1. **成本高**：云端 API 按调用计费，学校长期使用成本难以负担；
2. **隐私风险**：学习数据默认上传云端，涉及未成年人信息时合规压力大；
3. **低配设备无法运行**：大量学校、家庭设备无独立显卡，主流 AI 教育方案无法演示。

OpenMAIC 提出 MAIC 范式，用 AI 教师、AI 同学等多 Agent 组成虚拟课堂，是交互式教育的重要探索；但其默认依赖云端大模型，缺少面向国内 K-12 自学场景的学情长期记忆，也未针对低配硬件适配。

## 二、相关研究现状

### 2.1 多智能体教育系统

以 OpenMAIC 为代表的多智能体课堂通过多个 Agent 角色（教师、同学、导演）围绕同一学习目标开展讲授、提问、讨论与测验，让学习从"单向播放"变为"交互协作"。详见 `docs/reference.md`。

### 2.2 费曼学习法

费曼学习法强调"用自己的话讲给别人听"，是公认的高效学习方法。本项目将其落成可编排的五步流程：现象引入 → 认知冲突 → 思维模型 → 自主推导 → 费曼测试，并支持交互式单步引导（学生回答驱动 AI 调整下一步提问）。

### 2.3 本地轻量模型

自研 8M 参数微型 Transformer（从 tokenizer 到推理全部手写，CPU 可训练）与 Qwen2.5-1.5B 的 LoRA 微调量化模型（Q8_0，1.64GB），使纯 CPU 推理成为可能。

## 三、本项目工作

### 3.1 总体架构（四层）

| 层 | 职责 | 主要模块 |
|---|---|---|
| 模型适配层 | 统一抽象模型调用，屏蔽本地/云端差异，捕获异常与限流 | `framework/models/` |
| Agent 调度层 | 固定三角色（Teacher/Peer/Director）编排，职责不可混淆 | `goai_multi_agent.py` |
| 业务课堂层 | 文档导入、知识点拆分、会话管理、测验生成 | `goai_web.py` 等 |
| 持久存储层 | 会话/测验/错题/学情标签本地持久化并回流 | `framework/database.py` |

### 3.2 三项工程改良

1. **改良① 双模式适配**：Ollama 本地 / 云端 API 一键切换，低配 CPU 设备可完整演示（Ollama 默认推荐）。
2. **改良② 数理化业务适配**：覆盖"教—学—评—导"闭环，支持多端口服务（GOAI 学习 / 教师端 / 学生端 / Admin / 分析仪表盘）。
3. **改良③ 学情闭环**：学习记录、错题、答题标签写入本地知识库，后续课程动态调整难度，形成自进化闭环。

### 3.3 幻觉风险与安全设计

- 对模型生成的教学内容输出**幻觉风险提示文案**；
- 数据默认本地 SQLite 存储，不上传云端；
- 所有密钥走环境变量（`.env`），无明文密钥入库；
- 网络异常、429 限流、超时均有异常捕获与友好提示。

## 四、实验与验证（小范围案例，如实披露）

### 4.1 功能与回归测试

- pytest 核心测试 59 项 + 全产品回归 124 项全部通过；
- 多 Agent 专项 26 项通过；真实模型调用推理 56.9s，评分输出正常。

### 4.2 CPU 性能基准（真实环境实测）

| 指标 | 数值 |
|---|---|
| 推理速度 | 34.3 tok/s |
| 冷启动时间 | 3.5s |
| 三 Agent 串行全流程 | 56.9s |
| 峰值内存 | 1.77 GB |

测试环境：AMD Ryzen 7 7840HS，8 核 16 线程，15GB 内存，无独显。详见 `docs/performance-benchmark.md`。

### 4.3 标准化对比评测（30 题）

| 模型 | 答题正确率 | 幻觉错误率 |
|---|---|---|
| 自研 8M 模型 | 0%（能力如实披露） | 0%（无输出无幻觉） |
| Qwen-7B（远程 Ollama） | 96.7%（29/30） | 3.3%（1 例检测） |

评测方法：固定数理题样例，三档答案匹配（带单位→数值→文本）。详见 `docs/comparative-model-eval.md`。

### 4.4 局限声明（不回避）

- **未完成大规模对照实验**：仅基于小范围案例验证（30 题对比评测 + 真实服务运行），未编造百人统计实验；
- **本地 8M 模型能力上限**：答题正确率 0%，仅适合教学流程演示；
- **幻觉风险**：大模型可能生成看似合理但错误的内容，系统已做提示与检测；
- **学科覆盖**：聚焦数理化，未覆盖全学科；
- **并发未做压力测试**：多用户同时使用时响应可能延长。

## 五、结论与展望

LumiLearn 验证了"在低配 CPU 上运行多 Agent 交互式教学"的可行性，完成了对 MAIC 范式的应用层改良：双模式适配、数理化业务适配、学情闭环。系统存在客观局限（幻觉风险、本地模型能力上限、测试样本有限），有待后续迭代。

**未来工作**：将 Agent 调度内核抽离，重构为通用 Agent 运行时框架 **LumiFlow**，对外提供 Skill 插件兼容能力，LumiLearn 作为上层教育应用 Demo；扩充学科覆盖并开展真实用户小范围试用。
