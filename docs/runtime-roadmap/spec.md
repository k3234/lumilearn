# LumiLearn 未来发展规划

**日期**：2026-08-21
**状态**：草案，待纳入版本迭代
**定位**：面向教育场景的开源多-Agent 学习辅助平台，主打算力平权，普通 CPU 设备完整可部署。
**区分**：底层大模型基座依赖开源第三方，核心价值在于 Agent 调度、教学业务流水线、记忆管理、RAG 知识库、业务 Web 系统。

---

## 短期（3-6 个月）｜V2-V2.5 迭代（竞赛版本，单人可完成）

### 目标
加固现有闭环，补齐评测、稳定性、文档，完成参赛版本定型

### 1. Agent 层
- 优化多 Agent 流水线异常处理：单 Agent 调用失败时降级输出而非中断会话；增加超时控制、token 预算限制
- 优化记忆调度逻辑：区分短期会话记忆、章节记忆、错题记忆，减少无关历史上下文占用 token，降低 API 成本
- 增加 Agent trace 可视化面板：在后台直观看到每个 Agent 输入/输出、耗时、token 消耗，便于调试与竞赛报告展示

### 2. 知识库 RAG 模块
- 增强 BM25 检索：增加文档预处理校验，过滤坏文档；增加段落权重，优先使用教材类高可信度文本
- 支持导入 Markdown、EPUB 教学资料；对导入文档做格式校验，避免格式破坏知识库
- 输出内容标注引用来源片段，降低 AI 幻觉，便于学生、教师核对知识点

### 3. 评测模块（重点补强）
- 构建标准化学科测试集，自动统计：知识点召回率、习题正确率、幻觉出现频次
- 将评测结果输出可视化报表，写入技术文档；无需真实大规模用户，机器自动化评测即可

### 4. UI 与工程健壮性
- Lite 模式、完整模式开关更清晰；优化异常页面、输入边界校验
- Docker Compose 优化：配置文件与业务代码彻底分离，所有密钥走环境变量，禁止明文密钥
- 完善安全声明：明确工具边界、幻觉风险、数据本地存储说明，在 README、报告、演示页面三处呈现

### 5. 文档与开源交付
- 整理开发笔记、架构图、模块接口说明；区分自研模块/第三方依赖基座，清晰披露

### 约束
不做基座预训练，继续基于 Qwen、DeepSeek 等开源基座做 LoRA 微调、指令微调

## 中期（6-12 个月）｜V3 版本，生态与场景扩展

### 目标
从"演示 Demo"走向可用开源工具，拓展生态，不局限竞赛

### 1. Agent 内核解耦
- 将 LumiLearn 内部的 Agent 调度、记忆、Skill 工具能力抽离成独立 SDK 包（Lumi-Agent-Core）
- LumiLearn 本身变成上层教育业务应用；SDK 可被其他项目复用

### 2. Skill 插件系统
- 实现插件适配器层，兼容 MCP 协议；外部插件可接入：计算器、公式渲染、题库工具、文献检索
- 教育专用 Skill：数学公式校验、代码运行沙盒（用于理科仿真）、习题自动批改插件
- ⚠️ 沙盒执行代码安全风险高，个人只做接口对接，不实现本地不受限代码执行

### 3. 业务场景拓展
- 新增：学习计划自动编排、错题本导出、学习笔记生成
- 支持教师批量导入班级名单，批量学情导出
- 保留两种部署形态：本地私有化部署（CPU 优先）、云端 API 部署模式

### 4. 知识库能力升级
- 支持知识库版本快照，教师可切换不同版本教材知识库
- 支持知识库增量更新，无需全量重新导入

### 5. 开源运营
- 完善 issue 模板、贡献指引；接受外部开发者提交插件、学科知识库
- 产出演示视频、部署教程，降低上手门槛

### 风险点
- MCP 插件、SDK 重构工作量大，单人时间有限，优先保证业务版本稳定
- 不做 SaaS 公有云对外收费服务；只提供开源软件

## 长期（1-2 年）｜V4 架构演进

### 目标
架构演进，个人很难独立完成，需要团队/算力资助

### 1. 模型侧路线（不从零训练基座）
- **路线 A**：多教师蒸馏，针对教育领域做领域基座继续预训练；需租赁 GPU 算力，成本高
- **路线 B**：维持混合基座策略，投入重心放在上层 Agent 流水线、知识库、记忆调度、评测系统
- **更现实**：把上层系统做到足够优秀，而不是和大厂比拼基座训练

### 2. 架构方向
- 微服务拆分：知识库服务、Agent 调度服务、Web 业务服务解耦，可独立部署扩容
- 多租户支持，适合学校小规模试点部署

### 3. 产品边界严格守住
永远定位：AI 辅助教育工具，不替代教师；系统输出必须提示人工校验；不宣称教学效果 100% 准确

---

## 优先级取舍建议

### 优先做（高收益、工作量适中）
1. Agent 异常降级、trace 可视化
2. RAG 文档导入优化、来源引用
3. 自动化评测集与报表
4. 工程健壮、安全声明、文档完善

### 延后（工作量巨大，短期收益低）
1. 通用 Agent-Core SDK 完整重构
2. 大规模继续预训练基座
3. 不受限代码执行沙盒

---

## 赛道与商业化边界

1. **竞赛**：短期 V2.5 版本，作为主要参赛版本
2. **开源**：MIT 协议，软件开源，接受社区贡献
3. **商业模式**：不做公有云 SaaS 运营；允许学校、机构自行部署；可接受项目捐赠，不售卖软件许可
