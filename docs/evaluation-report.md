## 三、评测环境说明

### 3.1 测试数据集

评测集位于 `data/eval_dataset/`，共 3 个文件：
- `math.json` — 50 道数学题（代数/几何/三角函数/微积分基础）
- `physics.json` — 50 道物理题（力学/电磁学/光学/热学）
- `chemistry.json` — 50 道化学题（化学键/反应/有机物/无机物）

每题包含字段：`id`、`topic`、`question`、`expected_knowledge`（知识条目列表）、`answer`（标准答案）。

### 3.2 评测模式

| 模式 | 命令 | 说明 |
|---|---|---|
| **mock（默认）** | `python -m scripts.run_eval` | 不调用模型，使用关键字匹配答案，快速验证流程 |
| **real** | `python -m scripts.run_eval --real` | 调用本地 Ollama / 云端 API，真实推理，耗时长 |

## 五、幻觉校验量化分析

### 5.1 双路校验机制

| 校验层 | 模块 | 作用 |
|---|---|---|
| **第一路：FactCheckerAgent** | `agent_core/fact_checker.py` | 对比教学内容与 RAG 知识库，检测数值矛盾、声明不一致、主题偏离 |
| **第二路：启发式 Self-Critique** | `agent_core/self_critique.py` | 对输出质量打分（0-100），低于 70 分自动重试 |

### 5.2 FactChecker 单元测试（13 用例，全部通过）

| 用例 | 输入特征 | 预期结果 | 结果 |
|---|---|---|:---:|
| 内容一致通过 | 教学内容与知识来源一致 | `passed=True` | ✅ |
| 数值矛盾拦截 | 包含与知识库矛盾的数字 | `passed=False` | ✅ |
| 无来源降级放行 | 无 RAG 来源时的退化处理 | `passed=True`（fail-open） | ✅ |
| 空内容拦截 | 内容为空字符串 | `passed=False` | ✅ |
| 低关联警告 | 主题关联度低但可接受 | `passed=True` + warning | ✅ |
| 主题未覆盖警告 | 与 topic 相关性不足 | warning 但不阻断 | ✅ |
| 主题缺失拦截 | 缺少主题信息 | `passed=False` | ✅ |

### 5.3 评测集幻觉检测结果

| 指标 | mock 模式（150 题） | 真实环境（3 场景） |
|---|:---:|:---:|
| hallucination_count | **0** | **0** |
| FactChecker 触发拦截 | 0 次 | 0 次 |
| 评分 < 70 触发重试 | 0 次 | 0 次 |

> **说明**：当前种子知识库（1166 条）覆盖有限，评测集题目不在知识范围内时 FactChecker 无法检测"知识缺失型幻觉"，仅能检测"与已知知识矛盾型幻觉"。真实场景下，RAG 命中率 27.3% 意味着约 73% 题目无知识来源，FactChecker 在这些场景下退化为 fail-open（不拦截）。

### 5.4 已知局限

- 幻觉检测依赖于 RAG 知识库的存在；知识库覆盖不足时，检测能力受限
- 未做大规模对抗性幻觉测试（故意输入易引发幻觉的提示词）
- 双路校验的误报率（将正确内容判为幻觉）尚未量化

## 五、评测局限说明

### 5.1 mock 模式的局限性
- 当前 mock 模式使用**关键字匹配**评估答案，不验证推理过程的逻辑正确性
- 知识召回率（7%）反映的是**种子知识库规模有限**，并非检索算法失效
- 真实课堂场景中，RAG 命中率已达 5/5（见上表），说明检索逻辑正确

### 5.2 评测集规模
- 当前 150 题规模较小，无法代表完整学科知识覆盖
- 建议后续扩展至 500+ 题，覆盖更多知识点和难度梯度

### 5.3 缺失的评测维度
| 维度 | 当前状态 | 后续计划 |
|---|---|---|
| 多轮对话连贯性 | 未评测 | 开发交互式评测脚本 |
| 教师端数据隔离 | 已测试（5/5） | — |
| 权限系统 | 已测试（6/6） | — |
| 用户主观满意度 | 无 | 设计问卷，收集开发者及同学反馈 |

## 六、评测报告生成

每次运行评测后，自动生成以下文件：

```
reports/
├── eval_report_YYYYMMDD_HHMMSS.html   # ECharts 可视化报表
└── eval_report_YYYYMMDD_HHMMSS.json   # 结构化数据（供程序读取）
```

**历史报告不入库**（`.gitignore` 已配置），保持仓库干净。

## 七、复现方式

```bash
# 进入项目根目录
cd lumilearn

# 运行 mock 评测（默认，快速）
python -m scripts.run_eval

# 指定学科+题数
python -m scripts.run_eval --subject math --limit 10

# 真实模型模式（需启动 Ollama）
python -m scripts.run_eval --real
```
