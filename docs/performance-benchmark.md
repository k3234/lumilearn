# LumiLearn CPU 性能基准测试报告

> **报告日期**：2026-08-21
> **测试环境**：AMD Ryzen 7 7840HS（8 核 16 线程，15GB 内存，无独显）
> **推理引擎**：Ollama + lumilearn-v2（Qwen2.5-1.5B-Instruct，Q8_0 量化）
> **测试方式**：真实 SSH 远程服务器实测

---

## 一、基础推理性能

### 1.1 单次推理延迟

| 场景 | 耗时 | 说明 |
|---|:---:|---|
| 首次冷启动 | 3.50 s（含模型加载 1.31s） | 生成约 120 tokens |
| 热加载（服务常驻） | 3.53 s | 模型已加载，仅推理耗时 |
| 推理速度 | **34.3 tok/s** | CPU 16 线程满载 525% |

### 1.2 多 Agent 链路延迟

| 链路 | 耗时 | 说明 |
|---|:---:|---|
| FeynmanTeacher 单 Agent | 3.5 s（~120 tok） | 单个生成请求 |
| RAG 检索 + Feynman | 5.0 s | 检索 1166 条知识库后生成 |
| 三 Agent 串行链（Feynman→Score→Coach） | 56.9 s | 优化后（`num_predict` 限长修复，此前 284s） |
| 费曼五步完整教学 | 49–59 s | 化学共价键 49.1s / 数学勾股定理 59.2s |

> **关键优化**：2026-08-12 修复 `num_predict` 上限后，三 Agent 链路从 284s 降至 56.9s，**延迟降低 80%**。

## 三、低配硬件适配边界

| 硬件配置 | 可运行性 | 说明 |
|---|:---:|---|
| **4GB 内存 + 4 核 CPU** | ✅ **可运行** | 推理峰值约 2.6GB，余量充足 |
| 8GB 内存 + 4 核 CPU | ✅ 流畅 | 推荐配置，多用户场景稳定 |
| 2GB 内存 | ⚠️ 勉强 | 需调小 `num_ctx` 并启用 swap |
| 无 GPU（任何情况） | ✅ 不受影响 | 全程纯 CPU 推理，无需 CUDA |

**最低建议配置**：4GB 内存 + 4 线程 CPU + 5GB 磁盘（无独显、无 AVX-512 均可）。

## 四、已知性能局限

| 局限 | 说明 | 缓解方案 |
|---|---|---|
| 串行多 Agent 链路延迟叠加 | 当前三 Agent 串行，总延迟 ≈ 三单 Agent 之和 | Phase 2 规划并行化，预期降低 30–50% |
| CPU 并发请求处理 | 当前无分布式任务队列，多用户同时请求排队 | 已引入 SQLite broker 任务队列（P2-12，基础版） |
| 7B 模型在 CPU 上极慢 | qwen2.5:7b 推理约 8–12 tok/s，单次 60s+ | 文档明确推荐 CPU 使用 lumilearn-v2（1.5B） |
| 未做压力测试 | 未模拟 10+ 用户同时使用场景 | V3 规划补充压测 |

## 五、与云端 API 对比

| 指标 | lumilearn-v2（CPU） | DeepSeek API（云端） | 差距 |
|---|:---:|:---:|:---:|
| 推理速度 | 34 tok/s | ~50 tok/s（网络依赖） | 约 1.5 倍 |
| 单次响应 | 3.5s | 2–3s | 可接受 |
| 延迟波动 | 稳定（本地） | 依赖网络/配额 | CPU 更稳定 |
| 成本 | 零（本地） | 按 token 计费 | CPU 免费 |

> **结论**：CPU 推理在速度上比云端 API 慢约 30%，但零成本、零网络依赖，适合资源不足场景。
