# LumiLearn 复赛优化 — 用户体验专项方案

> **版本**: v1.0 | **日期**: 2026-08-15 | **状态**: 规划
> **优先级依据**: DeepSeek AI 分析（用户体验为第二优先级）+ 当前代码实际审查
> **核心结论**: 后端能力已具备（自适应引擎/交互式费曼/会话持久化），**缺的是前端接入与体验闭环**

---

## 一、用户体验现状诊断

### 1.1 已有能力 vs 用户体验缺口

| 后端能力 | 代码位置 | 状态 | 学生端是否可见 |
|:---|:---|:---:|:---:|
| 自适应学习引擎（知识图谱/进度/薄弱点/路径） | `framework/services/adaptive_learning.py` | ✅ 完整 | ❌ **无 API 无前端** |
| 交互式费曼单步引导（explain_step） | `framework/engines/feynman_engine.py` | ✅ 完整 | ❌ **学习页未使用** |
| 多轮对话持久化（chat_history） | `framework/services/conversation_store.py` | ✅ 完整 | ❌ **未关联会话** |
| 学习历史报告（learning_reports） | `framework/database.py` | ✅ 完整 | ⚠️ 仅列表查看 |
| 学习分析仪表盘 | `remote/templates/analytics_dashboard.html` | ✅ 完整 | ⚠️ 独立端口(18090) |
| 多 Agent 协作（教学→评分→建议） | `goai_multi_agent.py` | ✅ 完整 | ✅ 已接入 |

**核心诊断**：产品"后端能力过剩、前端体验断层"。复赛最大的 UX 提升 = **把已有能力串成学习闭环**。

### 1.2 学生使用痛点（推测）

1. **学完就忘**：报告看完就结束，没有复习提醒、没有进度留存感
2. **被动接受**：一次性生成完整讲解，学生没有"自主推导"的参与感
3. **不知道自己差在哪**：没有薄弱点可视化、没有下一步明确指引
4. **学习无连续性**：每次学习都是孤立的，系统不记得你是谁、学过什么

## 二、优化方向（按投入产出比排序）

### 方向 A：学习闭环串联 ⭐⭐⭐⭐⭐（投入 1，产出 5）

**目标**：让每次学习"有开始、有过程、有结果、有后续"

```
学生登录
   │
   ▼
┌──────────────────────────────┐
│ 学习首页（改造 goai_learn）  │
│  · 欢迎语 + 学习进度总览     │
│  · 薄弱点提醒（TOP3）        │
│  · 推荐继续学习（路径）      │
│  · 最近学习记录              │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 开始学习（交互式费曼引导）    │
│  · 五步逐步展开（非一次性）   │
│  · 每步后可追问/提出疑惑      │
│  · 第5步费曼测试要求学生作答  │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 学习报告 + 成果沉淀          │
│  · 掌握度评分（已有）         │
│  · 自动记录学习进度           │
│  · 更新薄弱点与推荐路径       │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 复习提醒（下次登录可见）      │
│  · "3天前学的X掌握度偏低"     │
│  · 一键复习入口               │
└──────────────────────────────┘
```

#### 具体任务

| 序号 | 任务 | 涉及文件 | 优先级 |
|:---:|:---|:---|:---:|
| A1 | 新增 `/api/learning/dashboard`：聚合进度/薄弱点/推荐/最近学习 | `goai_web.py` | P0 |
| A2 | 新增 `/api/learning/progress`：记录学习活动到自适应引擎 | `goai_web.py` | P0 |
| A3 | 改造 `goai_learn.html` 首页：进度卡 + 薄弱点提醒 + 推荐列表 | `remote/templates/goai_learn.html` | P0 |
| A4 | 改造报告区：完成后展示"已记录进度 + 推荐下一步" | 同上 | P0 |
| A5 | 新增 `/api/learning/path`：动态学习路径（含复习节点） | `goai_web.py` | P1 |

**实现要点**：
- 进度记录时机：学习报告生成成功后自动调用 `record_learning(user_id, node_id, score)`
- node_id 映射：由 RAG 检索命中的知识点或主题词匹配 `KNOWLEDGE_GRAPH`，未命中时兜底注册临时节点
- 进度数据源：`AdaptiveLearningEngine`（JSON 文件），与 learning_reports 表互补

### 方向 B：交互式费曼引导（深度追问）⭐⭐⭐⭐⭐（投入 2，产出 5）

**目标**：从"看报告"变成"参与学习"，让学生真正动脑

#### 当前问题
- GOAI 学习页一次调用 `/api/multi-agent` 生成完整五步，**五步一次性展示**
- `explain_step` 的 dialogue 交互模式**后端已支持但前端完全未用**

#### 优化方案

**模式选择**：保留"完整讲解"一键模式（快捷），新增"交互引导"模式（默认推荐）

```
[交互引导模式]                       [完整讲解模式]
① 现象引入 ──展示──→ 学生提问?    五步一次性生成
② 认知冲突 ──展示──→ 学生思考?    (保留现有，适合复习快看)
③ 思维模型 ──展示──→ 学生回答?
④ 自主推导 ──问题──→ 学生作答 ←─ 输入
⑤ 费曼测试 ──提问──→ 学生讲解 ──→ 评分+反馈
```

#### 具体任务

| 序号 | 任务 | 涉及文件 | 优先级 |
|:---:|:---|:---|:---:|
| B1 | 前端新增"交互引导"按钮，切换交互模式 | `goai_learn.html` | P0 |
| B2 | 新增对话式界面：逐步展示 + 学生输入 + 追问 | `goai_learn.html` + `goai_web.py` | P0 |
| B3 | `/api/multi-agent` 支持 `dialogue` 参数透传（已支持，需前端调用） | 复用现有 | P0 |
| B4 | 第5步费曼测试：学生讲解 → ScoreAgent 评分 → 反馈 | 复用多 Agent | P0 |
| B5 | 会话持久化：交互过程存入 chat_history，可恢复继续 | `goai_web.py` | P1 |

**关键设计**：
- 交互状态机：`step1→step2→...→step5`，每步结束后等待学生输入
- 学生输入选项：`继续`（默认）、`我有疑问`（触发 explain_step 追问）、`跳过`（仅展示）
- 费曼测试输入：学生的讲解文本 → 调 ScoreAgent 五维评分 → 反馈 + 更新掌握度

## 四、验收标准

### 4.1 功能验收

- [ ] 学生登录后首页可见：进度总览 + 薄弱点 TOP3 + 推荐下一步
- [ ] 学习完成后自动记录进度，再次登录可见"上次学到哪"
- [ ] 交互引导模式：五步逐步展开，每步可追问，费曼测试可评分
- [ ] 交互过程可保存为会话，下次可继续
- [ ] 薄弱点掌握度 < 0.7 时显示复习提醒

### 4.2 体验验收

- [ ] 从输入到首次反馈 < 2 秒（交互提示）
- [ ] 五步生成期间有进度反馈（非白屏）
- [ ] 移动端（375px）可用
- [ ] 无 RAG 命中、模型超时等异常有友好提示

### 4.3 测试验收

- [ ] 新增 API 单元测试 ≥ 10 个
- [ ] 前端核心交互走查通过（真实浏览器）
- [ ] 全量回归测试保持 382+ 通过

## 五、与现有规划的关系

本方案是对 [docs/复赛优化方向_v2.md](复赛优化方向_v2.md) 中"方向三：Prompt 工程与输出质量 / 方向四：Demo"的补充聚焦——**用户体验作为复赛首要差异化**，与多 Agent 升级（方向一）并行推进：

- 方向一（多 Agent）为后端能力，本方案为前端体验
- 交互式费曼引导（B 方向）直接复用方向一的多 Agent 协作
- 学习闭环（A 方向）与 RAG（方向二）联动：RAG 命中结果作为 node_id 映射依据
