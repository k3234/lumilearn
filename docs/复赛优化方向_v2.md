## 三、复赛优化方向（5 大方向）

### 方向一：多 Agent 系统升级 ⭐⭐⭐⭐⭐（最高优先级）

**目标**：从"串行三 Agent"升级为"可协作、可反馈、可自我批判"的多 Agent 系统

#### 3.1.1 当前架构

```
用户输入 → FeynmanTeacher(教学) → ScoreAgent(评分) → CoachAgent(建议) → 聚合报告
              (单向串行，无反馈回路)
```

#### 3.1.2 复赛目标架构

```
                    ┌─────────────────────────────────────┐
                    │         Orchestrator Agent          │
                    │      (任务分发 + 动态路由)           │
                    └──────────────┬──────────────────────┘
                                   │
            ┌──────────────────────┼──────────────────────┐
            ▼                      ▼                      ▼
   ┌─────────────────┐   ┌─────────────────┐   ┌─────────────────┐
   │ FeynmanTeacher  │   │  KnowledgeAgent │   │  DiagnosticAgent│
   │   (教学)        │   │   (RAG检索)     │   │   (学情诊断)    │
   └────────┬────────┘   └────────┬────────┘   └────────┬────────┘
            │                      │                      │
            └──────────────────────┼──────────────────────┘
                                   ▼
                    ┌─────────────────────────────────────┐
                    │     Self-Critique Agent (自评)       │
                    │  对输出质量进行评估，决定是否重试    │
                    └──────────────┬──────────────────────┘
                                   │
                            ┌──────┴──────┐
                            ▼             ▼
                   ┌─────────────┐  ┌─────────────┐
                   │ ScoreAgent  │  │ CoachAgent  │
                   │   (评分)    │  │   (建议)    │
                   └─────────────┘  └─────────────┘
                                   │
                                   ▼
                            最终学习报告
```

#### 3.1.3 具体任务

| 序号 | 任务 | 文件 | 预计工时 | 优先级 |
|:---:|:---|:---|:---:|:---:|
| 1 | 创建 `orchestrator.py`：任务分发 + 动态路由 | `framework/agents/orchestrator.py` | 2h | P0 |
| 2 | 创建 `knowledge_agent.py`：RAG 检索 Agent | `framework/agents/knowledge_agent.py` | 1.5h | P0 |
| 3 | 创建 `diagnostic_agent.py`：学情诊断 Agent | `framework/agents/diagnostic_agent.py` | 1.5h | P1 |
| 4 | 创建 `self_critique_agent.py`：自评 Agent | `framework/agents/self_critique_agent.py` | 2h | P1 |
| 5 | 升级 `MultiAgentOrchestrator`：支持反馈回路 | `goai_multi_agent.py` | 3h | P0 |
| 6 | 添加 Agent 间通信接口（Message Bus） | `framework/agents/message_bus.py` | 1.5h | P1 |
| 7 | 编写新 Agent 的单元测试 | `tests/test_*_agent.py` | 2h | P0 |

**关键设计决策**：
- 反馈回路阈值：当 `Self-Critique` 评分 < 70 分时，触发 FeynmanTeacher 重试（最多 2 次）
- 动态路由：根据学科/难度/学习类型，动态选择是否需要 DiagnosticAgent
- 超时控制：每个 Agent 独立超时，整体 Orchestrator 总超时 ≤ 180s

## 五、关键技术决策

### 5.1 Agent 协作模式选择

| 模式 | 优点 | 缺点 | 推荐 |
|:---|:---|:---|:---:|
| 串行（当前） | 简单、可控 | 无反馈、效率低 | ✅ 初赛已实现 |
| 并行 + 投票 | 速度快、鲁棒 | 结果可能冲突 | ⚠️ 可作为备选 |
| **串行 + 反馈回路** | **质量高、可控** | **实现复杂** | **⭐ 推荐复赛使用** |
| 完全并行 Agent | 灵活性高 | 调度复杂 | ❌ 超出范围 |

**决策**：复赛采用"串行 + 反馈回路"模式
- 主流程保持串行（便于调试和演示）
- 增加 Self-Critique 环节，质量不达标时触发重试
- 可选 DiagnosticAgent 并行预诊断（不阻塞主流程）

### 5.2 RAG 检索策略

| 策略 | 实现难度 | 效果 | 推荐 |
|:---|:---:|:---:|:---:|
| 纯关键词（当前） | 低 | 中 | ✅ 已实现 |
| 关键词 + 同义词扩展 | 中 | 中高 | **⭐ 复赛目标** |
| 关键词 + 语义向量 | 高 | 高 | ⚠️ 预留接口 |
| 纯语义向量 | 高 | 高 | ❌ 超出范围 |

**决策**：复赛采用"关键词 + 同义词扩展"，预留语义检索接口（`search_semantic()` 方法占位）

### 5.3 演示案例选择

推荐 3 个案例，覆盖不同难度和学科：

| 案例 | 学科 | 难度 | 推荐理由 |
|:---|:---:|:---:|:---|
| 函数的单调性 | 数学 | 高中 | 经典概念，费曼教学法效果明显 |
| 牛顿第二定律 | 物理 | 高中 | 有生活场景，容易理解 |
| 化学平衡移动 | 化学 | 高中 | 展示多学科支持 |
