# LumiLearn 数据合规说明（Privacy & Compliance）

> 日期：2026-08-12 · 初赛提交前
> 本文件说明 LumiLearn 在数据存储、账号权限、数据传输方面的合规设计，
> 符合《中华人民共和国个人信息保护法》《数据安全法》对教育类应用的要求。

---

## 一、核心合规承诺

1. **数据本地优先**：学生/教师数据、学习报告、推理日志全部存储在部署方自己的服务器（SQLite 数据库 `lumilearn.db`），默认不向任何第三方云端上传。
2. **AI 模型本地推理**：教学生成默认走本地 Ollama（CPU 推理），推理过程不发送原始提问到外部 API；仅在管理员显式配置云端模型 API Key 时可选使用云端推理。
3. **最小权限原则**：学生只能访问自己的数据；教师只能访问本班学生数据；管理员拥有全局管理权（可审计）。

---

## 二、账号权限管理体系

### 2.1 角色定义

| 角色 | 权限范围 | 说明 |
|---|---|---|
| **学生** | 本人数据 | 学习、提交解释、查看自己的学习报告与历史 |
| **教师** | 本班数据 | 班级/学生管理、学习监控、任务分配、发起数据导出申请 |
| **管理员（operator）** | 全局查看 | 查看全部用户/报告/推理日志/数据可视化 |
| **管理员（super_admin）** | 全局管理 | operator 权限 + 创建/启停/改角色/删除管理员与用户 |

### 2.2 数据范围隔离

- 教师端所有 analytics / 导出接口通过 `_visible_student_ids(teacher_id)` 限定为**本班学生**，无法跨班读取。
- 学生端学习报告仅绑定本人 `user_id`。
- 管理员可全局查看，但**所有操作记录审计日志**（`system_logs` 表）。

### 2.3 账号生命周期

- `users.is_active` 控制登录拦截：被禁用账号无法登录任何端口。
- 防锁死保护：不能禁用/删除自己；`super_admin` 角色账号不可删除。
- 管理员分级：`admins` 表独立管理（super_admin / operator）。

## 三、数据合规传输（管理员审批制）

### 3.1 数据导出审批流

```
教师发起导出申请（本班范围，注明用途）
        │
        ▼
管理员审批（pending → approved / rejected）
        │ approved
        ▼
教师仅可下载本人申请的导出文件（JSON / CSV）
```

- 导出类型：`reports`（学习报告）/ `reasoning`（推理日志）/ `answers`（答题）/ `users`（学生名单）/ `concepts`（知识点掌握度）
- 每条申请记录：申请人、类型、格式、范围、状态、审批人、申请/审批时间 → **全流程可审计**
- 管理员直接导出同样写入审计日志
- 导出文件存放在服务器 `export_data/` 目录，仅通过审批接口下载

### 3.2 为什么需要审批

教育数据属于敏感个人信息。即使在学校内部，批量导出学生数据也必须经过管理员授权，防止数据被未授权拷贝。审批制让每次数据流动都有记录可查。

## 四、技术安全措施

| 层面 | 措施 |
|---|---|
| **传输** | 服务默认绑定内网；对外部署建议置于反向代理（HTTPS）之后 |
| **存储** | SQLite 单文件，可通过部署脚本加密备份；`.env` 环境变量存放密钥，不进仓库 |
| **认证** | 密码 bcrypt 哈希存储；管理员独立登录会话 |
| **审计** | `system_logs` 记录登录、导出、权限变更等关键操作 |
| **代码安全** | 仓库已做深度脱敏：无真实 IP、无密码明文、无 API Key（仅 `.env.example` 占位） |

---

## 五、个人信息保护要点

1. **收集最小化**：学生账号仅收集姓名/用户名/密码哈希，不收集身份证号、家庭住址等无关信息。
2. **使用透明**：学习报告生成后学生本人可见，教师可见本班，管理员可见全局（有审计）。
3. **删除权**：管理员可删除用户账号（受防锁死保护限制）。
4. **教育场景特例**：本项目为校内教学演示，数据由学校自主掌控，符合《个人信息保护法》第 28 条关于不满十四周岁未成年人信息的特别保护要求——默认不采集任何可识别的生物特征或敏感信息。
